# time_study: t_cluster - t_veto per run type
Script `tcluster_minus_tveto.py CLUSTERS_TSV VETO_NPZ [--config legacy] [--bin 2] [--label T] [--out PNG]` (one sample in, one PNG out, fit rows on stdout).
- t_cluster = `seed_time_ns` of the benchmark `result_clusters.tsv` (`--cluster-times`; seed MF hit time, RAW: the benchmark logs print `time calib : off (0 modules with offset)`, so time_calib.json is NOT applied; the scan script subtracts it in-script), config `legacy`.
- t_veto = WaveAnalyzer CFD pulse time of V1..V4 (crate 3 slot 3 ch 0-3), largest-integral pulse per event and counter, from `../output/module_timing_20261030/dump/<run>_<split>.npz` (veto times do not depend on the HyCal calibration); no veto time calibration. Joined on event number.
- Fit: bin 2 ns; Gauss + constant, `curve_fit` on the bins within +-10 ns of the mode (start: mode, sigma 4 ns, median background; bounds a>=0, sigma>=0.2, c>=0); mu, sigma in ns, background in events/bin. "fit failed" is printed in the panel if it does not converge.
- Run all: `SCRATCH=<scratchpad> bash run_all.sh` (from this directory; writes `figures/` and `tables/tcluster_minus_tveto_fits.md`, and the pooled-veto and all-splits table/figures; the all-splits step needs `ts_025320_e100/` in SCRATCH).
- Data (one split per type; cluster TSV `$SCRATCH/ct_<type>_e100/<run_split>/result_clusters.tsv`): 0p73GeV_H2 024590_00050, 2p24GeV_H2 025228_00100, 3p49GeV_H2 024503_00050 (24386 not used: excluded from timing studies, notes/daq_queries_20261026.md).
- Ta X17 (25800, 26138, 26230): NOT made. The 10-30 dumps hold zero veto pulses for these runs (no veto data in Ta runs), so t_veto does not exist.
- Caveats: the 2 ns bin is coarse for the 0.73 GeV peak (sigma ~1.5 ns; its V4 background of 275 is a fit artefact). 2.24 GeV has a flat accidental pedestal. Sign is t_cluster - t_veto: peaks at +33 ns (0.73, 3.49 GeV) and -34 to -40 ns (2.24 GeV).

## Method scan and best method (2026-11-07)
Script `tcluster_minus_tveto_scan.py --scratch <scratchpad>` (about 1.5 min for all samples; `--veto-fit-pass SLUG` first, needs prad2py, for the log-normal veto variants) writes `tables/method_scan.md` (one row per sample, veto, cluster-time variant, veto-time variant, selection; BEST marked) and `figures/tcluster_minus_tveto_<slug>_best.png`. Samples: 0.73 GeV 024590/50, 2.24 GeV 025320/50 (benchmark rerun with the 025228 e100 job line, `--signal-min 100 --cluster-times --pulse-dump`, calib `PRad2_2p2_round1_4.json` (match), `runinfo/general.json`), 3.49 GeV 024503/50; 025228/100 is kept as a row `2p24GeV_H2_25228` for the record: it has no veto coincidence peak (the fits there find fluctuations of the flat accidental background, ignore them). The e100 `seed_time_ns` is RAW, so the earlier 1.2-4.2 ns widths were uncalibrated.
**Best method:** calibrated cluster time (seed-module offset of `time_calib.json` subtracted; the energy-weighted mean of the member MF times, members >= 50 ADC, is equal or marginally better than the seed MF time alone), veto pulse in time (+-10 ns around the first-pass mode) with integral > 2000 (largest integral), seed amplitude >= 500 ADC, fit on 0.25 ns bins with Gauss + constant within +-5 ns. Best sigma_fit per veto without the in-sample walk correction (V1/V2/V3/V4, ns): 0.73 GeV 0.36/0.37/0.37/0.36 (N 1.9k-5k, statistical error 0.01); 2.24 GeV (025320) 0.36/0.34/0.33/0.38 (N 350-750, error 0.02-0.03); 3.49 GeV 0.34/0.31/0.46/0.35 (N 100-160 in the scan rows, which count the log-normal/walk variants in +-5 ns; the single-split best recipe has N = 80-96 per counter, error 0.04-0.07, low-statistics and background-limited). The in-sample time-walk correction buys at most 0.01 ns and is not needed. The CFD cluster time (seed or weighted) is 0.07-0.12 ns worse than the MF time; the log-normal-fit veto time (77 % of veto pulses have time_algo 2) gives no gain over the CFD time; the Moller tag and the seed-amplitude cut change sigma by a few hundredths of a ns at most (the main effect is a smaller N); a veto height cut (>= 50, 100 ADC) is equivalent to the integral cut. No Veto template exists for the matched filter (the MF templates are PbWO4 only), so a veto MF time was not made; no |r-1| e-p cut was applied (E' is not in the cluster file), "noMoller" is the Moller-tag veto only. Ingredients, 2.24 GeV V2 (025320, sigma_fit in ns, old 2 ns / +-10 ns fit until the last step): today 0.90 (raw MF, largest integral) -> + time calibration 1.03 (no gain here, the 2 ns fit is dominated by the accidental pedestal; V3, V4 go 2.1 -> 0.51 and 1.8 -> 0.50) -> + in-time gate 1.08 -> + integral > 2000 0.48 -> + per-counter alignment (only matters for pooled V1-4, no effect on one counter) -> + 0.25 ns bins and +-5 ns window 0.36 -> + weighted cluster time, A500, no Moller 0.33. The robust width of the same peak is 0.43 ns (the +-5 ns window keeps accidental hits). Pooling V1-4 needs the per-counter alignment (0.73 GeV: 1.25 -> 0.48 in the old fit). Like-for-like with the earlier median-over-modules numbers (0.63 / 0.62 ns): median over seed modules with >= 30 hits of the core-fit sigma (iterative +-2 sigma, 0.2 ns) is 0.35 ns (124 modules) at 0.73 GeV and 0.35 ns (19 modules) at 2.24 GeV, robust width 0.43 / 0.62; it is lower than the earlier values because the sample is seed modules of E > 100 MeV clusters (large amplitudes) while the earlier one included all modules. At 3.49 GeV no module has 30 hits. All values are in-sample fits on one split per run; "best" picks the minimum of about 1800 combinations, so the quoted minima are optimistic by about their statistical error.

## Pooled vetos (2026-11-07)
`python3 tcluster_minus_tveto_pooled.py --scratch <scratchpad>` (about 20 s) runs the BEST recipe per counter on 0p73GeV_H2, 2p24GeV_H2 (025320), 3p49GeV_H2, fits each counter (0.2 ns bins, Gauss + constant, +-5 ns), subtracts mu_k and adds back the V1 mean (alignment to V1), concatenates the four aligned dt arrays and fits the merged histogram the same way (0.2 ns bins); the unaligned merge is fitted for reference. Writes `tables/pooled_vetos.md` and `figures/tcluster_minus_tveto_<slug>_pooled.png` (V1-V4 aligned, merged aligned, merged unaligned; 0.2 ns bins). Fit-only bin is 0.2 ns here, the scan table uses 0.25 ns. Result (sigma_fit +- err, robust, N; per-counter sigma in brackets V1/V2/V3/V4): 0.73 GeV merged 0.368 +- 0.006, robust 0.370, N 9271 (0.36/0.38/0.36/0.37), unaligned 0.93 (robust 1.21); 2.24 GeV 0.362 +- 0.015, robust 0.44, N 1450 (0.35/0.34/0.31/0.39), unaligned 0.82 (robust 1.33); 3.49 GeV 0.381 +- 0.028, robust 0.86 (accidental background inside +-5 ns), N 350 (0.47/0.29/0.41/0.35), unaligned 0.99 (robust 1.47). The aligned merge reproduces the per-counter width with about 4x the statistics; the error shrinks by about 2x. One event can enter several counters (each counter takes its own largest-integral pulse), so merged entries are not fully independent. The counter offsets (mu_k about 33.3-35.7 ns at 0.73 GeV, stable across samples) are why the unaligned merge is 2.5x wider.

**All splits.** `python3 tcluster_minus_tveto_allsplits.py --scratch <scratchpad>` (a few minutes) runs the identical recipe on every split of one run (0p73GeV_H2 run 24590: 10 splits; 2p24GeV_H2 run 25320: 8; 3p49GeV_H2 run 24503: 10) and concatenates the entries per counter. Inputs: benchmark outputs `<run>_<split>/` (frozen benchmark, `--signal-min 100`, `--cluster-times --pulse-dump`, runinfo `general.json`) in `<scratchpad>/ct_0p73GeV_H2_e100/`, `ct_3p49GeV_H2_e100/` and `ts_025320_e100/` (the 7 missing 25320 splits were produced with `crosstalk_study.run_benchmark(25320, split, work, 100.0)`, about 4 min each with 7 in parallel), and the veto dumps `output/module_timing_20261030/dump/<run>_<split>.npz`. mu_k is one value per run unless its scatter over splits is above the fit error (chi2/ndf of mu_k about its weighted mean > 2, centroid error sigma/sqrt(N in +-5 ns)), then it is taken per split (V1 run mean added back); both merged results are in the table. Writes `tables/pooled_vetos_allsplits.md` (per-counter mu/sigma/N, merged aligned and unaligned, splits and events used, mu_k per split and its scatter) and `figures/tcluster_minus_tveto_<slug>_pooled_allsplits.png`; the single-split outputs are unchanged. Result (sigma_fit +- err, robust, N; per counter V1/V2/V3/V4): 0.73 GeV (10 splits, mu_k per run, chi2/ndf <= 1.7) merged 0.367 +- 0.006, robust 0.370, N 89984 (0.355/0.377/0.362/0.369), unaligned 0.92; 2.24 GeV (8 splits, mu_k per split, V2 chi2/ndf 3.2, drift 0.04 ns) 0.354 +- 0.013, robust 0.414, N 12183 (0.369/0.361/0.330/0.357), unaligned 1.04; 3.49 GeV (10 splits, mu_k per split, chi2/ndf 10-11 for V1/V2, rms 0.12-0.13 ns) 0.423 +- 0.034, robust 1.13 (about 22 % accidental background in +-5 ns), N 3664 (0.46/0.40/0.40/0.38), unaligned 1.09. Per-run and per-split alignment give the same merged sigma within 0.003 ns. The 3.49 GeV scatter comes from fits on about 90 entries per split with background; it does not change the merged width.
