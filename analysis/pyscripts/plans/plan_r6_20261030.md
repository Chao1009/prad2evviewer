## Goal

R6 is the R5nr recipe with `--pos-corr` removed and the C++ energy-bias correction enabled inside clustering. That correction is `HyCalClusterConfig.energy_bias_correction`, applied at `prad2det/src/HyCalCluster.cpp:452-472`. Everything else is unchanged.

R6 is evaluated against R5nr on the 41 reference splits, with Ta per run and never pooled. A three-way ablation (R5nr, R5nr without pos-corr, R6) separates the effect of removing the Python map from the effect of adding the C++ correction. Promotion follows pre-declared criteria.

**Non-goals:**
- C++, binding or `database/` edits.
- Re-deriving gains.
- A 118-split rescan or an a/√E ⊕ b refit. These come only after promotion, through a plan amendment.
- The timing-gate and integration-range questions.

**Expected change size:** about 230 lines of new tools under `$O6/tools`: `r6_jobs.py` ≈ 100, `make_shadow_db.py` ≈ 30, `bias_table.py` ≈ 100. No tracked code is edited. Machine time is 12 + 78 + 82 jobs, about 4 h at -P 6.

## Approach

Each R6 job is generated from the 41 R5nr commands in `$O/jobs/abl_norefine.txt`. The generator makes four changes to each command:
- it drops `--pos-corr`;
- it drops `--cluster-profile geant4` (decision 2);
- it swaps the stem;
- it replaces the `merge_cfg_wrap.py` token with `$EBW --recon-cfg $CFG6 --carry --energy-bias`.

`$EBW` wraps `merge_cfg_wrap.py`, so `--hycal-cfg` and the runinfo handling are unchanged. It does two further things (`eb_wrap.py:1-30`):
- It carries the builder's `hycal_cluster_cfg` into the benchmark's clusterers. That config holds the bias-table pointer, which is C++-only and not exposed by pybind, and the Geant4 profile.
- It rescales member energies so that the `--gain-file` rebuild keeps the cluster factor.

Re-derived tables are loaded without touching `database/`. Each run type gets a shadow database directory (`PRAD2_DATABASE_DIR=$O6/db_<name>`) whose entries are symlinks to `database/`, except `energy_bias/`.

Rejected alternatives:
- *Edit `_make_cluster` to copy the bias fields.* The table pointer is not bound in Python: `python/bind_det.cpp:777-786` exposes only the flag. The gain rebuild would also still drop the factor.
- *Bind `HyCalEnergyBias`, or change `HyCalCluster.h:52-55`.* Both are C++ changes and need a rebuild (R5 decision 5).
- *Use the `poscorr/scan_norefine` view as the "no pos-corr" arm.* Only its `result_clusters.tsv` is refine-off. Its `result.tsv` is a symlink to the refine-on run (benchmark d91af9b7), so `compare_scan_dirs.py` would read stale numbers.

## Decisions

1. **R6 definition.** R6 is the R5nr command of each split, minus `--pos-corr`, plus the C++ bias. Everything else in that command is kept:
   - gains `$O/gains/<run>/` and the config `$O/configs/reconstruction_config_r5.json`;
   - `--moller-reject kin 3/2`, `--fit-select chi2 --cb-two-peak` and `--gain-refine off`;
   - the Geant4 profile, now carried by `$EBW` (decision 2);
   - `--window 16.0`, and the same banks, calibration files and LMS.

   `$CFG6` differs from the R5 config only in `energy_bias_correction` (`reconstruction_config_r5.json:20`).
2. **Code path: `$EBW` unchanged, and no `--cluster-profile geant4` token in `$EBW` arms.**
   - Under `--carry`, the carried config already has the builder's Geant4 profile, and `set_config(cfg)` installs it in both clusterers.
   - Keeping the token would break every job. The benchmark's SimpleProfile self-check twin copies `cl_legacy.get_config()`, which then also has Geant4, so the split check fails and `sys.exit` is called (benchmark:2721-2746).
   - R1 (S1) proves that the carried config, including the profile, reproduces R5nr's clusterer exactly.
3. **Order relative to gains; gains are not re-derived.**
   - C++ forms `E = cl.energy · bias_corr · linear_corr` at the cluster position, after the leakage step (`HyCalCluster.cpp:452-472`). The lookup is nearest-bin in the centre-module frame (`HyCalEnergyBias.h:71-106`).
   - The benchmark rebuilds Σ gᵢEᵢ (benchmark:3225-3234). `$EBW` scales the members by E/ΣEᵢ, so the result is f(cell)·Σ gᵢEᵢ, which commutes with the gains.
   - For the calibrated energy, the kin Møller rejection and the fit, the factor acts where `--pos-corr` did: after the gains and before the refinement (benchmark:3241-3270, 3303, 3463).
   - Unlike `--pos-corr`, the factor also enters the in-loop selection on `r.hit.energy` (the `signal_min` single-cluster cut, the veto, and the "pre" energies; benchmark:2872-2888). R2 reports the size of this effect.
   - R5 already derives the gains before any position correction (`plan_r5_20261028.md:121`), so the R5nr gains are reused.
   - Caveat: the repo tables carry a per-module mean bias. Over nonzero cells, for modules with at least 20 such cells, it has a median of +0.29 % and a spread (SD) across modules of 0.32 % for 2p2, and +0.27 % and 0.33 % for 0p7/3p5. On top of the R5nr gains this acts as a gain perturbation. The re-derived tables are normalised to remove it (decision 6).
4. **"Default switched on" = recipe default**, per Open Question 1(a), until the user answers.
5. **The repo tables do not fit R5nr. These facts are behind Open Question 2.**
   - *No provenance.* The only keys are `comment`, `description` and `W1…W1152`.
   - *Built for a different calibration.* They were built in September (commits 3282b6e and 5b750e3, YuanLiSDU, 2026-09-22/23) from C++ replay ROOT files with that replay's calibration. The tool takes no gain input (bowl_shape:122).
   - *Partly placeholders.* `0p7GeV_*` and `3p5GeV_*` are cell-for-cell identical and carry the comment "same with 2.2 GeV e-p, wait to be updated". Only the 2p2 files were updated (5b750e3).
   - *ee is a copy of ep.* The `ee` files equal the `ep` files cell for cell; the tool uses only the `ep` expectation (bowl_shape:235).
   - *Coverage.* Only PbWO4 is covered; lead-glass modules get 0 (`HyCalEnergyBias.h:91`). The tables do not know the target: Ta and C at 2.24 GeV both use the 2p2 set, chosen as the nearest of 700, 2200 and 3500 MeV to the runinfo Ebeam (`HyCalEnergyBias.h:31-44`; `PipelineBuilder.cpp:430-451`).
   - *Sparse and clamped.* Cells with fewer than 200 entries are 0, and values are clamped to ±0.03 (bowl_shape:238-245).
   - *A unit bug.* The tool passes `atan2(r, z)`, in radians, to `PhysicsTools::ExpectedEnergy(theta_deg, …)` (bowl_shape:179-183 and 231-235; `analysis/src/PhysicsTools.cpp:272-274`). This shifts each module's expected energy, so it mainly enters the per-module mean. It is a report for the tool's author; R6(b) does not use the tool.
6. **Form of the re-derived tables (`r6rd`).** They mirror the R5nr maps, with one shadow database per slug.
   - *Source.* `$O/poscorr/scan_norefine/result_clusters.tsv`, the same input as the R5nr maps, read through `position_corr.load_pool`, which drops `moller_rej`. The ratio is r = E_cal/E′, as in position_corr.
   - *Cells.* As in `HyCalEnergyBias.h:71-98`: cell = clamp(floor((off + 0.5)·5), 0, 4), with off = (x_cl − x_seed)/size.
   - *Peak per cell.* `position_corr.fit_ratio` for n ≥ 400; the mean for 200 ≤ n < 400; bias = peak − 1.
   - *Normalisation.* Each module table, and each pooled grid, is shifted to an occupancy-weighted mean bias of 0 before the ±0.03 clamp. This is the bias-space equivalent of the maps' mean-1 normalisation (`position_corr.py:32`, `:44`). It keeps the tables from acting as an in-sample per-module gain refinement, which the refine-off contract excludes.
   - *Per slug.*
     - 3.49 H2, 2.24 H2 and C get per-module tables. A cell with n < 200 takes the slug's pooled cell (the hybrid fallback).
     - 0.73 H2 gets the pooled grid for every module (R5nr's bilinear map).
     - Ta gets the 2.24 H2 pooled grid (R5nr's Ta map).
   - *ee.* `_ee.json` is a copy of `_ep.json`, as in the repo.
7. **Circularity.**
   - R5 has no held-out scheme: its maps are in-sample over all 118 splits, including the 41 reference splits, and R3's even/odd check was not repeated (`plan_r5_20261028.md:244`).
   - For parity, `r6rd` is in-sample.
   - A diagnostic arm, `r6rd_ho`, uses tables derived with `--exclude-splits $O/configs/ref41.txt`. The difference r6rd − r6rd_ho measures the in-sample advantage. It is reported and not used for promotion.
8. **Evaluation.**
   - *Baseline:* `$R5NR` on the 41 reference splits (16 e-p/C + 25 Ta).
   - *Statistic:* paired per-split Δ, mean ± SE, per run type and per Ta run (25800, 26138, 26230, never pooled), legacy and gated.
   - *Headline:* CB core σ, with the Gaussian as the secondary column (10-29 decision 1). A |CB − Gauss| disagreement is flagged, not resolved; `ablation_table.py` does this.
   - *Arms:* `nopos` (R5nr minus `--pos-corr`), `r6db`, and, under Open Question 2(b), `r6rd` and `r6rd_ho`.
   - *Contrasts:*
     - nopos − R5nr: the value of the Python map;
     - r6x − nopos: the value of the C++ bias;
     - r6x − R5nr: the net effect;
     - r6rd − r6rd_ho: the in-sample advantage.
9. **Gate scan.** R6 does not depend on `output/gatescan_20261030/` and runs at R5nr's 16 ns gate. That scan covers 1–8 ns on the R5nr recipe; on 10-30, 566 of its 615 jobs had finished. If it changes the gate default, R5nr and R6 are rerun together later, outside this plan. Because of machine capacity, S2 starts only after the gate scan finishes. The capacity gate is the R5 formula with `pgrep -f 'merge_cfg_wrap.py|eb_wrap.py'`.
10. **Promotion. R6 replaces R5nr as the working reference only if all of P1–P4 hold.** The criteria are fixed before any result and use the R5 rules (`plan_r5_20261028.md:208-215`):
    - **P1.** The S1 checks R1 and R2 pass, and 0 jobs fail.
    - **P2.** At each of the 4 e-p/C points, on the CB headline, legacy and gated: Δ(R6 − R5nr) ≤ −1 SE.
    - **P3.** Each Ta run is within 1 SE of R5nr or better, legacy and gated.
    - **P4.** Post `eps_peak` is within ±0.5 % of R5nr per type.

    If P2 or P3 fails, R6 is reported and not promoted, and R5nr stays.

11. **User decisions 2026-10-30 (approved; resolve Open Questions 1-3).**
    - OQ1 = (a): "default switched on" is per R6 job via `$EBW --recon-cfg $CFG6 --carry --energy-bias`. No change to `database/reconstruction_config.json` or any global default; no `database/` writes.
    - OQ2 = (b): tables re-derived on the R5nr gains, zero mean per module. R6 = `r6rd`; `r6db` (repo tables) and held-out `r6rd_ho` are reported alongside; `nopos` arm as planned.
    - OQ3: provenance by recorded checksums (`git_state.txt`) of `$EBW`, `merge_cfg_wrap.py` and the new R6 tools, as R5 did. The user commits or copies them later. S2 is not blocked on that; the executor does not commit.
    - Option (b) of decision 6 does not use `analysis/tools/hycal_energy_bowl_shape.cpp` (confirmed: tables come from `bias_table.py` on `result_clusters.tsv`). The radians/degrees bug at its lines 179-183 and 231-235 is reported to the user, not fixed here.

## Risks

- **Member energies are rescaled.** The `$EBW` member rescale also scales the members written to `result_clusters.tsv` and the percrystal arrays. That is harmless here, but these TSVs must not feed a future gain or map derivation.
- **Coarse lookup.** A 5×5 nearest-bin table is coarser than the hybrid poly8 map: a bowl of about 2 % depth gives a step error inside each cell. This is a property of the C++ path and part of what R6 measures.
- **Statistics.** A full per-module table needs about 5000 elastic clusters per module (25 cells × 200). Outer modules fall back to the pooled grid. In the repo, 29 % of the 2p2 cells are zero.
- **Silent disable.** An Ebeam ≤ 0 in runinfo turns the bias off silently (`PipelineBuilder.cpp:447-451`). The S2 `set_choice` test catches it.
- **Shared machine.** The gate scan and the intscan/pedfloor jobs share the machine (decision 9).
