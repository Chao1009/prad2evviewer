## 1. Goal and approach

**Goal.** Derive the R5 reference = R4 (best-50 e-p/C banks, best-200 Ta bank, per-crystal gains, position maps) re-derived at the R5 clustering settings (seed 30 MeV, log_weight_thres 5.2, merged code) with kinematic Møller rejection in the calibration and in the sample, evaluated on the same 118 splits (93 e-p/C + 25 Ta, per run) with the two-peak CB / χ² fit selection; attribute the change to each ingredient on the 41 reference splits; refit a/√E ⊕ b; decide promotion over R4.

**Approach.** Same three-pass chain as R3/R4 (F6): (a) percrystal dump pass → per-crystal gains; (b) scan with gains and no position correction → position maps; (c) final scan with gains + maps + Møller rejection + fit selection. Each pass runs the working-tree benchmark through `merge_cfg_wrap.py` so that the seed override is in-process (no `database/` write), from job lists derived token-by-token from R4's `job.cmd` files so that only the intended tokens change. Møller rejection enters the per-crystal solve as an offline filter in `percrystal_calib.py` on the dump arrays (`E_cluster`, member energies, `eprime_MeV`, `emoller_MeV` already stored, F4), which avoids a new benchmark mode.

Rejected alternatives (one line each):
- Harness `gate_scan_20261022.py run`: builds the benchmark command itself (`build_cmd`), cannot prefix the wrapper, and points `--hc-calib-file` at the pre-merge `calibration/` path; job lists from R4 `job.cmd` are already the R4 way (F6).
- Keeping R4 gains/maps and only switching the clustering (merge_check variant (b)): the +0.02 pp log_weight penalty measured there was with maps derived at 3.6; the summary's own promotion condition for seed 30 is "gains and position maps re-derived".
- Deriving a Ta map from Ta data: R3/R4 apply the 2.24 GeV H2 bilinear map to each Ta run (F5); kept — decision 4 forbids pooling the Ta runs and a single Ta run cannot populate a map.

### S1. Order of derivation and the convergence check

Order: **gains → maps → final scan**, as R3/R4 (F6). Reasons: the percrystal dump is written before `--gain-file`/`--pos-corr` and the percrystal solve takes neither (F4), so gains cannot depend on a map; the map derivation needs `cluster_E_cal_MeV`, i.e. gains applied, and must not have a map applied (F5), so maps depend on gains. The clustering settings change both (seed 30 changes membership and the per-module pool; log_weight 5.2 changes the centroid, hence (u, v) of every cluster and the map shape), so both are re-derived. No gain ↔ map iteration: the map has mean 1 per module by construction and the final scan's seed-indexed refinement absorbs any per-module residual (F7). Convergence is **measured, not assumed**: after S4, `python3 $O/tools/window_gain_check.py --scan-dir $O/scan/r5_splits --ref $R4 --ref-ta $R4TA --out $O/tables/window_gain_check.tsv` pools `result_window.tsv:gain` over used modules per run type (Ta per run) for R5 and R4; pass = Definition "Converged". Failure → second pass: `g2 = g1 × gain_M` folded into a new gain table (`$O/gains_pass2/<run>/`), then S3–S4 again (≈ 4 h); not expected (R4 did not need it).
