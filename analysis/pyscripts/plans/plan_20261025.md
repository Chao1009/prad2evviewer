## 1. Goal and approach

**Goal.** Lower the post-refinement σ_E/E of the PbWO4 inner ring on local data by (2) removing the remaining amplitude dependence of the template energy, (1) correcting the cluster energy for the impact position inside the seed crystal, (3) settling LMS gain tracking for the 12 runs that have no gain-correction file (a two-run on/off check with the files the local splits allow, a measured drift bound for the rest, full files deferred to ifarm), and (4) testing three clustering constants, in that order, with a user checkpoint after the position map; record everything in a new dated note and refit the resolution decomposition at the end.

**Approach.** Every item is measured with the existing tools and the paired statistics of the previous rounds: the driver produces the one new reference scan (item 2), the harness runs every variant with `bench_args` and the `{run}`/`{runtype}` placeholders (no driver change), `compare_scan_dirs.py` pairs variant and reference per (run, split), `plot_module_resolution.py` makes the per-module maps. New code is confined to: two cluster-TSV columns and three small opt-in flag groups in the benchmark (`--pos-corr`, clustering constants), configurable amplitude bands and an optional per-module f(A) in the template tool and bank, finer bins in the study tool, and one new script `position_corr.py`. Defaults stay byte-identical (G0 check after each benchmark edit).

**Rejected alternatives (one line each).**
- A driver `--bench-args` passthrough for the variant scans: the harness already has placeholders, split filters and job resume; the driver is needed only for the item-2 rescan, which uses existing flags.
- Building the position map from the NPZ dumps (which already carry `x_cl, y_cl`): the dump holds pre-gain energies, so the seed-indexed step would have to be re-implemented offline; the cluster TSV route uses the benchmark's own post energies and `plot_module_resolution.py`'s loader, at the cost of two TSV columns.
- Implementing amplitude-indexed templates (option ii) in the matched filter before the cheaper options are tested: it changes the time fit and therefore the pile-up and timing tables; evaluated offline first (§4.4), implemented only on a separate go.
- Per-module position-correction coefficients (PRad-I, 8 per module): statistics (≈ 2–20k pool events per module and run type) do not support 8 parameters per module; a map per run type first.
- Refitting per-crystal gains for every clustering variant: + 2.75 h each; done only for a variant that wins (§7).

### 5.3 `position_corr.py fit` and the benchmark flag

- `fit --map map_<slug>_<set>.tsv --form bilinear|poly8 --out output/poscorr_20261025/<slug>/poscorr_<slug>_<set>.json` (schema `poscorr_v1`: `form, run_type, slug, u_edges, v_edges, R[12][12], n, se, norm, poly {c0…c7} if poly8, source {scan_dir, splits, fit, n_events}, created, git`). **bilinear** (default, D4 of `plan_20261023`): the binned R normalised to a population-weighted mean of 1 (the energy scale is unchanged on average), bilinear interpolation between bin centres, clamped to the outer bin centres, ±0.55 (`B:376-377`). **poly8**: the PRad-I denominator `1 + c1u² + c2v² + c3u²v² + c4u⁴ + c5v⁴ + c6u + c7v` (`docs/analysis_notes/cluster_density_correction.md:278-294`) fitted to the bins with weights 1/se², normalised the same way. Both forms are written; only the default is scanned (Q4).
- `fit --global`: the five per-type maps pooled (each normalised) → `poscorr_global_<set>.json` and `consistency_global.tsv`: per run type, the fraction of populated bins where |R_type − R_global| ≤ 2·hypot(se); **global is used only if ≥ 95 % of bins pass in every H2 and C run type**, else per run type (Q3). Ta is never fitted (≈ 1k pool events per split); it gets the 2.24 GeV H2 file symlinked under its slug and is reported only.
- **Benchmark `--pos-corr FILE`** (default off): sets `rec_ext`, and for every event of both paths replaces `e[6]` by `e[6]/R(u, v)` **after `--gain-file` and before the window fit** (between `B:2378` and `B:2418`; `size_x/size_y` from `module_by_id`). Header line `# pos_corr=<path> sha1=<..> form=<..> norm=<..> n_applied=<..> n_clamped=<..>`. Justification for "before" (Q2): the seed-indexed g_M are refit in every job and absorb the per-module residual mean of the map; the per-module CB/Gaussian pre-fit sees the narrower peak, so the windows and the Møller separation improve; for a normalised map, "after" is equivalent to first order and gains nothing. The pooled per-crystal gains are not refit after the correction (they are fit on member energies, which the cluster-level factor does not touch; first-order unbiased because the map has mean 1).

## 11. Risks and compatibility

| Risk | Mitigation |
|---|---|
| The f(A) residual is population-dependent (F9): bands derived from clean candidates may not flatten the in-window study pulses, and the 2-SE rule is very tight at n ≈ 50k per bin | §4.1 measures both populations before any build; acceptance is on the study pulses with the spread reported; the fallback is the smallest-spread option (Q1); the production Δ is the final arbiter |
| A 2000–4000 ADC band has per-module statistics only at 3.49 GeV; 0.73 GeV has nothing above 1000 | Knot = median over the modules that have the band (as now); f constant above the last knot; n_modules recorded per knot |
| Changing f(A) moves every mf energy → the gains must be refit; the pile-up tables are not redone | Dump pass + `fit` before the scan (§4.5); the pile-up caveat goes in the note |
| The map is in reconstructed coordinates (S-shape compression, 0.1–0.15 resolution); edge bins hold true edge hits of several positions | Map and correction share the coordinates; `n` map and the σ map after the correction show what is irreducible; `--min-n 300` and neighbour filling for sparse bins |
| Even/odd split sets must be identical between the map tool and the harness | `position_corr.py` imports `G.r_pairs()` and the harness's 0-based rule (F10); the JSON records the split list; the executor diffs it against the harness `--dry-run` job list |
| The harness prepends `--mf-scale 1.01` for mf (F10) | Every `bench_args` ends with `--mf-scale 1.0`; `job.cmd` and the `kappa=1` header of one job per tag are checked before a tag runs |
| Harness variants hold 118 splits (no 24386.00060) while R1 holds 119 | All comparisons are paired on common splits by `compare_scan_dirs.py` |
| LMS cannot be applied to 10 of the 12 runs with local data (F12) | See §6: two-run check, recorded drift bound, deferred ifarm item |
| Gains not refit after the position correction or per clustering variant | First-order argument stated; confirmation pass with refit gains for any adopted change (Q6) |
| Another scan on the machine during an edit or a run | `pgrep` idle check before edits and scans; wall times assume exclusive use |
| Ta: ≈ 16 calibrated modules and ≈ 1k pool events per split | Never fitted or mapped; receives the 2.24 GeV H2 map file; reported only |

### B. Per-module position correction (PRad-I style) vs the per-run-type map

**Protocol.** Training r = E_cal/E′ comes from the offline R1 chain, with r in [0.85, 1.12] and (u, v) as in `position_corr.py`. The run-type map's even/odd split sets are used: train on one half, apply to the other. The correction replaces R2's map; everything else is as R2.

**Forms.**

| Form | Definition |
|---|---|
| (a) | Run-type bilinear, held-out (`poscorr_<slug>_{even,odd}.json`) |
| (b) | Run-type poly8 |
| (c) | Run-type HCNOTE: R = c0·(1 + c1·e^(c2 − c3/u²))·(1 + c1·e^(c2 − c3/v²)), with c2 fixed at −0.1152 because c1 and c2 are degenerate |
