## Goal

Rebuild the R5nr resolution chain (dump -> per-crystal gains -> map scan -> position maps -> final scan)
on the calibration files that `database/runinfo/general.json` assigns to each run, with the per-module
non-linearity `1/(1 + nl1 δ + nl2 δ²)` of those files applied as production does (`prad2det/src/HyCalCluster.cpp:457-473`).
Rerun the two one-setting variants on that basis: R7ri (W0 per run type) and fAri (template banks without
f(A)). Report absolute σE/E per point and path for each arm, plus paired Δ (variant − R5nr-ri) within the new basis.

Non-goals: any comparison with R5nr or other old-calibration outputs (user instruction 2026-11-04: "regenerate the new
absolute results"); re-deriving template banks; touching `output/r5_20261028`, `output/r7_20261104`,
`output/fA_ablation_20261104` outputs (their configs and banks are read).

Expected change size: one ~6-line edit to the benchmark (Open Question 1) + ~5 new scripts of ~40-80 lines each
under `output/r5ri_20261104/tools/`, three output trees, ~1065 benchmark jobs.

## Approach

- The benchmark's two clusterers already run with the C++ default `non_linear_corr=true`
  (`benchmark_hycal_timing_test_20261021.py:2697-2716` copies only 8 config fields; `prad2det/include/HyCalCluster.h:51-55`
  defaults nl on, leakage off, bias off). So `r.hit.energy` (dump `E_cluster`, headline spectrum) already carries the production
  nl factor with the seed module's constants and skip rules, while the member hit energies `h.energy` are raw
  (`cal_factor × adc`, `prad2det/include/HyCalSystem.h:153-157`, times the LMS factor at :3016/3024). With `--gain-file` the cluster energy is rebuilt as Σ gᵢEᵢ from those raw members
  (:3225-3236), which drops nl. Nothing in the old chains' outputs ever exercised this because every old/ file has nl=0
  (`notes/rerun_inventory_20261104.md`, which also records that `--gain-file` drops nl and bias completely).
- Chosen mechanism (A): a new benchmark flag `--nl-members on|off` (default off) that, inside `member_rec`
  (:2780-2796), rescales the member energies by `r.hit.energy / Σ h.energy`, i.e. the C++ cluster-level factor
  (nl only, since bias and leakage are off). Then the dump's `E` carries f, the gain fit sees Σ gᵢ(fEᵢ) = f Σ gᵢEᵢ, and
  the `--gain-file` rebuild in the map and final passes carries f automatically. Production's δ (raw cluster energy,
  per-module `base_energy`, seed module's nl1/nl2), the `E > 3800 MeV` cutoff and the `[0.7, 1.3]` clamp are all honoured
  because the factor is taken from the C++ replay, never re-implemented.
  Rejected: scaling only the dump post hoc (map/final passes would stay nl-free; inconsistent); applying f after gains/maps
  (raw ΣEᵢ and seed are not in `result_clusters.tsv`, and the headline histograms are built inside the benchmark); folding f into
  per-module gains (f belongs to the seed, not to each member; not exact); an in-process wrapper like `merge_cfg_wrap.py`
  (`member_rec` is a closure of `main()`, the rebuild is inline: nothing to patch); folding gains into the calibration JSON
  (`--pos-corr` and `cluster_E_cal` exist only on the gain-file path, which bypasses nl again).
- Everything else is the R7 chain shape (`output/r7_20261104/tools/chain_r7.sh`): one generator, one chain script
  parametrised by chain name, one table script, all in `output/r5ri_20261104/tools/`; r7ri and fAri hold outputs only.
- Tables: `compare_scan_dirs.py --scans R5nr-ri=… R7ri=… fAri=…` (first label is the reference `A`,
  `compare_scan_dirs.py:217-235`) gives one `_splits.tsv`; `ri_table.py` prints absolute columns per arm and Δ columns
  per variant in the `r5nr_table.md` layout, plus a/√E ⊕ b per arm on the three H2 points (`nr_table.fit2`).

  Reason: exact production mirror, consistent gain fit, no re-implementation. Requires the benchmark edit (Open Question 1).
- D2 (A, validation): on one 0.73 GeV split and one ≥25200 split, run the dump pass with the flag off and on; per cluster
  `ΣE_on/ΣE_off` must equal `E_cluster/ΣE_off` (flag off) and the Python factor from the JSON (seed `nl1`, `nl2`,
  `base_energy`, δ = (ΣE_off − base)/1000, skip rules) within 1e-5 (dump `E` is float32); for the ≥25200 split all three are
  exactly 1. With the flag on, `member_identity` violations in `result.tsv` are 0.
- D3 (A, regression): the edited benchmark with the flag off reproduces the pre-edit benchmark byte-for-byte on one split.
  Order: before the edit, run the generated r5ri dump line of scan_025320/split_00100 with the `--nl-members on` token
  removed, via `output/r5_20261028/tools/run1_sha.sh`, stem `output/r5ri_20261104/regress/pre/`; edit; rerun the same
  line with `--nl-members off` via `run1_ri.sh`, stem `regress/post/`; `cmp` `result_clusters.tsv`, `result_window.tsv`
  and `result_dump.npz` (`result.tsv` except `elapsed`). A code check on fresh outputs, no old numbers.

  from the rerun-inventory work; same rule as `prad2det/include/RunInfoConfig.h:208`: largest `from_run ≤ run`, chained

  Ebeam (0.73 GeV runs 24590/24603 → `calibration_factor_3p5_June7_nonLinear.json`, tag 3p5), but only warns when the file
