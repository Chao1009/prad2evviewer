## 4. Phase 1: the mf pulse reconstruction

### 4.1 Template bank (new module `mf_pulse.py`, class `TemplateBank`)

- **Load** `output/pulse_templates_h50.dat` (path from `--mf-templates`, default this file). Take τ_r, τ_f from the 25320 columns (D2). If a value is NaN, take the 25308 column.
- **Validity rule.** A module's pair is used only if 1.0 ≤ τ_r ≤ 6.0 ns and 15 ≤ τ_f ≤ 35 ns. This rejects W1019 and W1020 (F2) and nothing else in today's file.
- **Fallback.** PbWO4 modules that are missing (W1124, and any other W module in the geometry without a row) or invalid get the PbWO4 aggregate (τ_r 2.499, τ_f 24.41 ns; values read from the 25320 JSON `_by_type`, path recorded). PbGlass and Veto channels keep the WaveAnalyzer peaks unchanged in mf mode (their calibration factors are 0, F5).
- **Per module, precompute** (indexed by `mod.index`):
  - a kernel bank `K[m, φ, l]` = p(l·4 ns − φ·1 ns) for onset phases φ = 0, 1, 2, 3 ns and l = 0 … L−1, with L = 24 samples (96 ns, past 3.5 τ_f); and `‖K[m, φ]‖²`;
  - `t50[m]`: the leading-edge 50% time of the unit-peak template, relative to t0 (matches the WaveAnalyzer CFD convention, F6);
  - `I_wa[m]`: the **WaveAnalyzer-equivalent integral per unit amplitude**. Build noise-free uint16 waveforms (pedestal 200 + 2000·p(t − t0), 100 samples, t0 at the 4 phases near sample 25), run the existing `p.wave_ana.analyze` on them, and average `pk.integral / 2000` over the phases. This reuses the exact C++ smoothing and tail-walk rule (F5) without re-implementing it.
- **Header line** (mf only): `# pulse_method=mf templates=<path> sha1=<sha1> column=25320 n_module=<n> n_fallback=<n> fallback=<W1019,W1020,W1124,...>`.

### 4.2 Peak finding (design item a)

Per event, in mf mode:

1. **Per channel (existing loop).** Keep `ped_mean, ped_rms, wa_peaks = p.wave_ana.analyze(cd.samples)`. For PbWO4 channels, copy the samples into a preallocated event buffer `Y[n_ch, N]` (float32) and record `mod.index`, `ped_mean`, the LMS factor and the time offset. Nothing else runs per channel in Python.
2. **Batched, per event.** `y = Y − ped_mean[:, None]`. Raw noise σ = 1.4826·MAD of the raw samples 0–29 (the WaveAnalyzer pedestal window); the smoothed `ped_rms` underestimates raw-sample noise.
3. **Candidate channels.** Keep a channel if the maximum of its 3-sample moving average exceeds `max(3σ, 3 ADC)`. Only candidates go on.
4. **Matched filter.** For candidates, `C[n, j, φ] = Σ_l y[n, j+l] · K[m_n, φ, l]` via `sliding_window_view` and one `einsum`; amplitude `A = C / ‖K‖²`; significance `S = A / σ_A` with `σ_A = σ / ‖K‖` (the prototype's white-noise scaling, §3).
5. **Accept and subtract (iterative).** Per channel, take the (j, φ) with the largest S. Accept it if `A ≥ max(nσ · σ_A, A_min)` (defaults `--mf-nsigma 5`, `--mf-min-amp 5` ADC; D4). If an earlier accepted peak's kernel span covers this onset, also require `A ≥ r_model · A_parent` with `r_model = 0.05`, so template-misfit residuals on large pulses (2–3%, F4) are not accepted as pulses. Subtract the refined template (step 6) and recompute C on the residual for the channels that accepted a peak. Stop at `--mf-kmax 4` peaks or when nothing passes.
6. **Sub-sample time (design item c).** Fit a parabola to `C²/‖K‖²` at the best phase and its two neighbours on the 1 ns grid (wrapping across samples). Its vertex is the starting t0. Then run 3 batched Gauss–Newton iterations on (a, t0) per peak: residual `y − a·s(t − t0)`, Jacobian columns `s` and `a·∂s/∂t0` from the analytic template (F4), a closed-form 2×2 solve per peak. The parabola alone leaves up to 0.6 ns time and 1% amplitude errors on noise-free pulses, because the template has a kink at onset; the Gauss–Newton steps remove them (a noise-free check during review: max 0.0014 ns and 0.002%). The reported time is `t = t0 + t50[m] − toff[m]`, so it is on the same convention as `pk.time` and the existing pre-window (100–200 ns) and `--time-calib` offsets still apply.
7. **Joint amplitude fit (design item b).** For every channel, solve the K×K normal equations `G a = b` with `G_ik = ⟨s_i, s_k⟩`, `b_i = ⟨y, s_i⟩` over the union of the peaks' windows (K = 1 reduces to A = ⟨y,s⟩/⟨s,s⟩). Batch by K (most channels have K = 1; ≥ 2 peaks in 1–5.5% of channels, plan_20261021 F11). If any a_i ≤ 0, drop that peak and solve again. Then re-run step 6 (parabola and Gauss–Newton) once for each peak on `y − Σ_{k≠i} a_k s_k`, and solve the amplitudes once more. No further iteration.
8. **χ²/dof** over the union window with σ² + (0.03·a·s)² per sample (the extraction's model floor). Stored in the dump and the stats line, not used as a cut.

Peaks with t outside the pre-window are dropped exactly as today. The legacy path takes the largest-energy mf peak per module, the gated path takes all of them: the same downstream code as `B:1195-1209`.

### 4.3 Saturation and clipped samples (design item e)

- A sample is clipped if its raw value is ≥ the `overflow` value of the wave config (4095).
- Channels with a clipped sample in the search range skip the batched path. Each one gets a per-channel masked fit: weights 0 on clipped samples, then steps 4–7 on the unclipped samples only (the leading edge and the tail fix A and t0).
- If fewer than 6 unclipped samples remain in the pulse's window, or fewer than 2 on the leading edge, use the WaveAnalyzer peak for that pulse and count it as a fallback.
- Header line: `# mf_stats n_cand=.. n_peaks=.. n_multi=.. n_joint=.. n_sat=.. n_sat_fallback=.. n_fallback_template=..`.
- Incidence is unknown (F8). V8 measures it; V3 tests the masked fit on a noise-free clipped pulse. If V8 finds clipped samples in more than 1e-3 of pulses above 1 GeV, add a test on real pulses clipped artificially before Phase 3.

### 4.4 Energy scale (design item d)

- **Definition.** `E_units = A · I_wa[m] · κ`, then `mod.energize(E_units · f_LMS)`, as for rawsum. `κ` is one global constant, `--mf-scale` (default 1.0), written to the header.
- **Why the integral-equivalent and not the area.** The calibration factors are MeV per WaveAnalyzer integral unit (F5). The elastic-window refinement sets one gain per **seed** module and multiplies the whole cluster energy by it (`B:359-490`, applied at `B:487-488`). A per-module scale error on the neighbours therefore does not cancel. `I_wa[m]` puts each module's amplitude on the scale its calibration factor expects, with no data pass. The full template area (∫p dt ≈ 7.8 samples for the aggregate) differs from the integral by about 8% (the tail cut at 10% of height) and by module through τ_f.
- **What the refinement absorbs.** Any remaining global offset, and per-seed-module constants, as for rawsum (the 2.24 GeV calibration already sits +7.5% high and is absorbed, note §4.3).
- **What it cannot absorb.** An amplitude-dependent ratio. At high amplitude mf and rawsum should agree; at low amplitude the WaveAnalyzer walk stops earlier (the `ped_rms` condition), so mf/rawsum is expected to rise above 1 for small pulses. V6 measures this; mf is linear by construction.
- **κ.** Set κ ≠ 1 only if V6 finds the pooled median `E_mf/E_rawsum` for 0.5–2 GeV pulses outside 1 ± 0.01. Then κ = 1/median, measured on 025320 split 00050, and fixed for Phases 3 and 4.
- **Rejected:** a per-module data-driven scale table (needs a pre-pass per run period; revisit only if V6 shows a per-module spread > 2%); re-deriving the calibration factors for mf (C++ `physics_calib`, out of scope).

### 4.5 Performance (design item f)

- **Budget.** Event-loop time (`elapsed_s` header) with mf ≤ 1.5× rawsum on the same split (target), ≤ 2.0× (hard limit). At 2.0× the Phase 4 scan stays within about 2× of Phase 1's 4.3 h (§7.3). Above 2.0×, stop and ask the user before Phase 3.
- **Design.** No per-channel NumPy calls: one buffer write per channel, then a fixed number of batched operations per event (the candidate cut, one `einsum` per subtraction round, the parabola, the batched solves). The saturated-channel path is per channel but rare.
- **Measured in V10** on 20,000 events of 24503 split 00010 and 25320 split 00050: loop time per method, mean channels per event, candidates per event, mean peaks per candidate.
- **Levers if over budget**, in order: restrict the search to onsets in samples 0–55 (pulses that can reach the pre-window or pile into it); raise the candidate cut to 4σ; reduce φ to 2 phases (parabola on a 2 ns grid). Numba is not used without the user's agreement (new dependency).

- **Implementation deviations (executor, 2026-10-22).** (a) `MIN_SEP_NS` = 12 ns minimum onset separation between peaks in a channel (acceptance mask both directions, plus drop-the-smaller after the joint Gauss–Newton): without it mf split ~15% of large pulses into main + a −6 ns "pre-pulse" (ratio ~0.25), which made V11 trip the stop rule (+0.30 pp on 025320 legacy Gaussian). (c) The joint refinement is a joint Gauss–Newton on all (a_k, t0_k) of a multi-peak channel. (d) κ = 1.011 (V6 0.9894 on 025320.00050) was the r_model 0.05 value, used only for the first Phase 3 run (archived in `phase3_r005/`). **With r_model 0.3 (Round 3, step 1), κ = 1.010; every later mf job, including all of Phase 4, uses κ = 1.010 and r_model 0.3.**
