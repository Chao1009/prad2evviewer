## 1. Goal

1. **Phase 1, which runs first.** Scan the cluster timing gate and find out whether a better gate makes the gated ("new") clustering beat legacy on σ_E/E. Today gated is 0.02–0.04 pp worse on e-p and C, and 0.02–0.14 pp better on X17 Ta.
2. **Phases 2–7.** Put the user's four upstream items in order and plan them: per-module waveform characterisation, pile-up deconvolution, peak sensing, and per-pulse timing. Each one is measured through the same Phase 1 harness.

The paper plan's headline claim is that "cluster-level timing-gated waveform calibration improves PRad-II energy resolution". The project needs Phase 1 to settle that claim.

**What follows from these facts.** The gated path has been tested only at W = 8 on raw times. With raw times, the 2.7 ns module offset spread is about three times the corrected Δt resolution, so W = 8 drops real in-time neighbour hits and shifts their energy into the low tail. That fits gated being slightly worse on low-pile-up e-p runs and better on the X17 runs, which have 5× the pile-up. So the time reference (raw or offset-corrected) is a gate parameter, and Phase 1 scans it.

## 3. Phase 1: timing-gate scan (execute first)

### 3.1 Parameters scanned

| Parameter | Meaning | Exposed today? | Change needed |
|---|---|---|---|
| Time reference | Raw `pk.time`, or `pk.time − offset[module]` from `time_calib.json` | No | New benchmark flag `--time-calib {off,auto,PATH}`, default `off` |

### 3.2 Code changes

**A. Benchmark (additive; with no new flags, the output is bit-identical to today's).**

1. `--time-calib {off,auto,PATH}`, default `off`.
   - `auto` resolves to `$PRAD2_DATABASE_DIR/hycal_time_offsets/time_calib.json`, or `<repo>/database/...` when the variable is unset.
   - Load `modules[]`. For each entry with `resolved` true, set `off[module_by_id(module_id).index] = offset_ns`. Every other module, including PbGlass, gets 0. Print the count of modules that have an offset.
   - Apply `t = pk.time − off[mod.index]` **before** the pre-window test and before `add_hit`, in both paths. This matches `Replay.cpp:1016`, where `Analyze` subtracts the offset before the window cut.
   - Header line: `# time_calib=<path|off> n_offsets=<n>`. A missing file exits 2, with no silent fallback.
2. Efficiency counters. These are written as `#` header lines only, so the table schema and `parse_tsv` stay unchanged:
   - `# cluster_counts legacy n0=.. n1=.. n2plus=.. new n0=.. n1=.. n2plus=..` counts events with 0, 1, or ≥ 2 clusters above `--signal-min`.
   - `# paired n_same_seed=.. dE_frac_mean=..` covers events where both paths have exactly one cluster with the same seed module. It uses `dE_frac = E_new/E_legacy − 1` on the raw (LMS-corrected, pre-refinement) cluster energies. This is the direct measure of the energy the gate removes.
   - `# peak_yield nsigma=2.5 s_ref=.. modules_common=.. legacy=.. new=..` is written only with `--calibrate`. It takes the modules used by both paths, then for each path counts the pool events with `|E_corr/T_M − 1| ≤ 2.5·s_ref`. `s_ref` is this job's legacy post-refinement Gaussian σ/E, and `T_M` is the module's refinement target.
3. Nothing else changes. Defaults, the TSV tables, PNGs and other outputs stay as they are.

**B. New harness `analysis/pyscripts/gate_scan_20261021.py`.** It does not modify the driver.

- It imports `_HC_CALIB_MAP`, `_PRE_WINDOW_MAP`, `_DEFAULT_PRE_WINDOW`, `_DATABASE_DIR`, `_BENCHMARK_SCRIPT`, `gain_corr_path`, `_run_type` and `_EXCLUDED_RUNS` from the driver, and uses them read-only.
- The per-job command is the driver's command (driver lines 353-368) with `--window W --time-calib {off|auto}`, `--pre-window LO HI` and the optional `--bench-args` string appended:


- Subcommands:
  - `run --stage {A,B1,B2,C} --half {A,B} [--configs-file F] [--bench-args S] [--baseline DIR0] --out DIR --parallel N --timeout-seconds T [--dry-run] [--force]`.
    - It only launches jobs and returns; it does no aggregation.
    - It manages a plain `subprocess.Popen` pool with a polling loop and does not reuse the driver's `concurrent.futures` pattern, which hangs after the workers finish (plan_waveform.md, open item E).
    - A job is skipped when its `result.tsv` exists and its header matches the job (`pre_window`, `seed_time_window`, `time_calib`, and the bench-args recorded in the manifest). `--force` reruns it.
    - Failures and timeouts go to `DIR/failures.tsv`, and `run` exits non-zero if there are any.
  - `summarise --out DIR [--baseline DIR0]` parses **both** paths from every `result.tsv` and writes the tables and plots listed in §3.6. It may reuse the driver's `parse_tsv`, which returns both paths.
  - `select --stage {A,B1,B2} --out DIR` parses the `result.tsv` files itself, so no prior `summarise` is needed. It applies the §3.5 rule to the tune half and writes `DIR/selection_<stage>.json`. Stages B1, B2 and C read the earlier selections from `DIR`, and a CLI override is available.
  - `--baseline DIR0` points at a finished scan, normally `output/gate_scan_20261021`. With it, `run` takes the stage selections from `DIR0`, and `summarise` also computes Δ against `DIR0`'s working-point rows on matching (run, split) pairs. This is how later phases compare against the Phase 1 working point.
- `--configs-file` takes a JSON list of `{tag, time_calib, W, LO, HI, bench_args}`. Later phases use it to scan their own knobs with the same machinery.
- `DIR/manifest.json` records the git HEAD and dirty flag, the benchmark's sha1, `--bench-args`, the grid, the split halves and timestamps. A re-run after an upstream change uses a new `--out` (for example `output/gate_scan_<date>_<tag>/`).

### 3.5 Figure of merit and selection rule

- **σ_E/E.** The post-refinement σ_E/E uses each run type's preferred fit: CB for 3.49 GeV H2, C and Ta, and Gaussian for 2.24 GeV and 0.73 GeV H2.
  - It is computed from the calibrated block of `result.tsv`, rows `legacy` and `new`: `sigma_cb_MeV/mu_cb_MeV` (CB) or `sigma_post_MeV/mu_post_MeV` (Gaussian).
  - The `sigma_over_E_*` fields are not used. They are rounded to 4 decimals (0.01 pp steps), which is too coarse for a 0.02–0.04 pp effect.
- **Paired differences.** Both are computed per split. For each run type, report the mean and SE = SD/√n, using only splits where every config involved exists.
  - `Δ_s(c) = σ/E_new(c) − σ/E_legacy(ref)`, where ref is the legacy row of `traw_w8_pmap` for the same split. This measures the whole setting against today's legacy, and it drives the selection.
  - `Δgate_s(c) = σ/E_new(c) − σ/E_legacy(c)`, both from the same job. This measures what the cluster gate adds on top of the same pre-window and time reference. It answers the Phase 1 question.
- **Efficiency.** A tighter gate must not win just by discarding events, so two efficiencies are tracked:
  - `ε_yield(c) = Σ n_events_new(c) / Σ n_events_legacy(ref)`, the single-cluster yield from the headline table.
  - `ε_peak(c) = Σ peak_yield_new / Σ peak_yield_legacy`, taken within each job (§3.2 A.2).
  - Also reported: `dE_frac_mean` and the `n2plus` counts.
- **Selection rule.** It is applied on half A only:
  1. The candidates are every config of the stage except the W = 100 reference.
  2. Keep the candidates with ε_yield ≥ 0.99 and ε_peak ≥ 0.99 in **every** run type.
  3. Compute the mean of Δ over the five run types, each run type weighted equally. Its pooled SE is `sqrt(Σ_r SE_r²)/5`.
  4. Among the configs within one pooled SE of the minimum, take the largest W. On a tie in W, take the wider pre-window. On a tie between time references, take the lower mean Δ.
  5. Also report each run type's own optimum, as a diagnostic.
- **Over-tuning guard.**
  - The headline numbers come from half B only (stage C).
  - Flag the result if `|Δ_A(c*) − Δ_B(c*)|` is larger than twice the combined SE.
  - The gate counts as an improvement only if Δgate_B < 0 by more than 2 SE. The hand-off claim is stated in terms of Δgate_B.
- **Determinism check.** Within one split and one time reference, the legacy headline row (`n_events`, `gauss_mu_MeV`, `gauss_sigma_MeV`, `n_in_fit`) and the calibrated `n_inner_events` must be identical across the stage A W values. The legacy calibrated σ must be identical only where the `target_mean_MeV` header is the same, because the calibrated fit window uses the mean E' of both paths' pools (benchmark :1279, :1296). Elsewhere it must agree to within 0.005 pp.

### 3.10 Rejected alternatives

- **Extend the driver with gate flags.** It is in use by other jobs, its aggregate names collide, and its summary table (`extract_row`) reads only legacy.
- **Run several W values in one benchmark pass.** It would save about 60% of stage A CPU, but it changes the TSV schema and the refinement per path. Revisit it if re-runs become the bottleneck.
- **Full 2-D pre-window grid.** It is 16 configs instead of 7, and 24386 already shows LO is flat from 50 to 130.
- **Choose on all splits.** That gives no protection against over-tuning.

## 4. Phases 2–7: the user's items, ordered

Item 4 (per-pulse timing) is split in two. **4a** calibrates the timing that already exists. It is cheap, needs nothing from items 1–3, and directly sets how tight the gate can be. **4b** builds a better per-pulse time estimator, which needs items 1 and 3. Item 3 is split into **3a**, the integration and threshold settings of the existing finder (cheap; changes every pulse energy), and **3b**, a new hybrid finder.

**Common success test.** Each item's change enters the benchmark as a flag that is off by default. It is tuned on half A through `--configs-file` and confirmed on half B: `gate_scan_20261021.py run --stage C --half B --baseline output/gate_scan_20261021 --bench-args "<flag>"`, then `summarise --baseline output/gate_scan_20261021`. ### 4.1 Phase 2: item 4a, timing calibration and energy-dependent gate

- **Goal.** Make the gate's time comparison as good as the hardware allows, and make W energy-dependent as the paper plan requires.
- **Current state.**
  - `pk.time` is a tiered estimator: quadratic vertex, then 50% linear CFD above 5σ_ped, then a log-normal CFD fit above 10σ_ped (`prad2dec/src/WaveAnalyzer.cpp:497-589`).
  - Offsets exist but have no provenance field (F5). Corrected σ_t comes from F6.
  - There is no energy-dependent W (F1).
  - The seed-time distribution has two humps 12 ns apart (F7), which is unexplained.
- **Approach.**
  1. **Energy-dependent window.** Add a C++ `ClusterConfig` field `seed_time_window_e0` (MeV, default 0 = off, bit-identical). Use `dt_max(E_hit) = W · max(1, sqrt(e0/E_hit))` at `HyCalCluster.cpp:200` and `:336`. Bind it in `bind_det.cpp:705-727`, rebuild prad2py, and add the benchmark flag `--window-e0`. Scan e0 ∈ {0, 20, 50, 100} at W* using `--configs-file`.
  2. **Offset validity.** Re-derive offsets with `module_dt_diagnostic.py` on one run per period (24503, 25320, 26230). Compare them with `time_calib.json`. If the per-module differences have an RMS above 0.5 ns, build a table per period and select it by run in `--time-calib auto`.
  3. **Time walk.** From the same diagnostic, take the mean corrected Δt against neighbour energy. Add a walk correction only if the shift between 20 MeV and 1 GeV is larger than 0.5 ns.
- **Success metric.**
  - The harness gives Δ_B(W*, e0*) ≤ Δ_B(W*, 0), with ε ≥ 0.99.
  - The corrected Δt σ against energy table becomes the paper's σ(t) input.
- **Dependencies.** Phase 1 (W* and the time-reference result). A C++ rebuild is needed (decision D7).

### 4.2 Phase 3: item 3a, integration and threshold settings

- **Goal.** Tune the existing per-pulse energy estimator. It sets the photostatistics-versus-noise trade-off for every hit in both paths.
- **Current state.**
  - `pk.integral` sums smoothed, pedestal-subtracted samples outward from the peak. It stops after `tail_break_n` = 2 samples below `max(int_tail_ratio·height, rms)`, with `int_tail_ratio` = 0.1.
  - The threshold is `max(peak_nsigma·rms, min_peak_height)` = `max(5·rms, 10 ADC)`, and smoothing is 3-tap (`WaveAnalyzer.cpp:345-465`; `database/daq_config.json:100-113`).
  - Every `WaveConfig` field is settable from Python (`python/bind_dec.cpp:297-313`). None has been scanned against σ_E/E.
- **Approach.**
  - Add the benchmark flag `--wave-cfg KEY=VAL` (repeatable). It sets `p.wave_ana.cfg.KEY` and is written to the header.
  - Scan one knob at a time at the Phase 2 working point: `int_tail_ratio` ∈ {0.03, 0.05, 0.1, 0.2}; `peak_nsigma` ∈ {3, 4, 5} with `min_peak_height` ∈ {5, 10}; `smooth_order` ∈ {1, 2}.
  - The per-module refinement absorbs a constant integral fraction, so only the resolution matters.
- **Success metric.** Δ_B of the gated path at the working point, and legacy reported beside it. Yields must not drop, because a lower threshold must not add noise clusters (watch `n2plus`).
- **Dependencies.** None beyond the Phase 1 harness. It runs after Phase 2 so the gate is settled first.

### 4.3 Phase 4: item 1, per-module waveform characterisation

- **Goal.** Build per-module pulse shape, pedestal noise and integral linearity tables with enough statistics to drive the finder, timing and deconvolution. Also find out whether the 2.24 GeV bimodality is a waveform effect.
- **Current state.**
  - Per-channel τ_r, τ_f and t0 medians are in `output/pulse_templates_*.json` (`fit_pulse_template.py`, two-τ model). Only 384 of 1151 modules have ≥ 20 good pulses in `pulse_templates_025308_h50_RawSum_max20modules.json`. τ_f varies by 7.7% across modules (range 9–30 ns).
  - The C++ `PulseTemplateStore` uses only the per-type aggregate (`prad2dec/include/PulseTemplateStore.h`), and the benchmark does not use it.
  - The 25308 extraction gives a PbWO4 aggregate of τ_r 2.46 ns and τ_f 23.97 ns (`fit_pulse_template.md:64-65`). The file production points to, `waveform/pulse_templates_024177.json` (`database/daq_config.json:118`), has τ_r 7.38 ns, τ_f 38.55 ns and `n_channels_good` 0 for PbWO4. That matches the background shape (Population B), not physics pulses.
  - The two-τ model has a 2–3% leading-edge misfit (`fit_pulse_template.md` §4a).
  - A background shape population (Population B) makes up 21% of pulses in 26138.
  - `Module::energize` is linear and ignores the non-linearity coefficients (`prad2det/include/HyCalSystem.h:154`).
  - 30–35% of modules are bimodal in 25260, 25299 and 25320, and none in 24386. The effect is static in time and its mechanism is open (`output/bimodality_scan/`; `plan_waveform.md`, open item A).
  - Pedestal autocorrelation is not measured anywhere.
- **Approach.**
  1. **Bimodality triage, first and cheap.** On 25320, run the benchmark with `--write-cluster-tsv` and split the events of the top bimodal modules (for example W593) by hump. Compare the seed pulse τ, t0, peak count and the pre-window position (F7's two time humps) between the humps. If the humps track the waveform or time features, fix that in the estimator. If they track kinematics or trigger, record it as physics and stop.
  2. **Full-statistics per-module templates.** Run `fit_pulse_template.py` over all local splits of 25308 and 25320, aiming for ≥ 100 good pulses per inner-ring module. Add the discrete (non-parametric) average shape (plan_waveform.md §3c) alongside the two-τ parameters.
  3. **Pedestal tables.** Per-module pedestal RMS and autocorrelation from the first 30 samples of physics events, as input to 3b and 2.
  4. **Integral linearity.** Per module, the ratio of `pk.integral` to the template integral against amplitude. A non-constant ratio is an effective non-linearity that the per-module gain cannot absorb.
- **Success metric.**
  - Coverage: ≥ 90% of inner-ring modules with ≥ 100 good pulses.
  - Discrete templates reach χ²/dof ≈ 1 without the 0.03 floor.
  - Bimodality gets a verdict.
  - Any estimator change from steps 1 or 4 is measured through the harness (Δ_B), with the 2.24 GeV H2 Gaussian σ/E the main target.
- **Dependencies.** None. It feeds 3b, 4b and 2.

### 4.4 Phase 5: item 3b, hybrid peak finder

- **Goal.** Find the small second pulses that WaveAnalyzer misses.
- **Current state.**
  - The WaveAnalyzer separation floor is 24 ns at amplitude ratio ≥ 1 and 48 ns at ratio 0.5, and it is blind below about 30% amplitude.
  - The matched-filter prototype finds 76–96% at ratio ≤ 0.3 and ΔT ≥ 48 ns, against 6–18% for WaveAnalyzer. WaveAnalyzer is better at ΔT = 24–32 ns with equal amplitudes (`benchmark_matched_filter.py`; `fit_pulse_template.md` §6-7).
  - `find_peak.md` is a walkthrough with no measurements.
- **Approach.** Follow plan_waveform.md §3a: WaveAnalyzer first, then the matched filter on the residual using the per-module kernel from item 1, then merge the peak lists. Expose it as the benchmark flag `--peak-finder {wa,hybrid}`.
- **Success metric.**
  - Synthetic: detection efficiency on the `output/pileup_synth_025308` grid, with no loss at ratio ≥ 1.
  - Harness: Δ_B on X17 Ta and e-p, with `n2plus` and yields watched for fake pulses.
- **Dependencies.** Item 1 (kernels, pedestal noise).

### 4.5 Phase 6: item 4b, template-fit per-pulse time

- **Goal.** Get a per-pulse time from a template fit that also works for overlapping pulses.
- **Current state.** The CFD times are good for isolated pulses (corrected σ 0.85 ns above 100 MeV, F6). Pulses that the deconvolution separates get only the WaveAnalyzer CFD time (`benchmark_hycal_timing_deconv.py` uses `pk.time`).
- **Approach.** Fit t0 with the per-module template from item 1 for each pulse found by 3b. Use it in place of `pk.time` behind the flag `--time-estimator {cfd,template}`.
- **Success metric.**
  - Corrected Δt σ against energy is no worse than CFD for isolated pulses.
  - Harness: Δ_B at W*, and stage A rerun with the new estimator to see whether W* moves.
- **Dependencies.** Items 1 and 3b.

### 4.6 Phase 7: item 2, pile-up deconvolution

- **Goal.** Recover the correct energy of overlapping pulses. The paper's bonus claim (ΔT_min) also comes from this item.
- **Current state.**
  - `WaveAnalyzer::Deconvolve` is a joint Levenberg-Marquardt fit with 4 parameters per peak, a per-type two-τ template and white noise. It is seeded only by WaveAnalyzer peaks and disabled in production (`prad2dec/src/WaveAnalyzer.cpp:825-1123`; `database/daq_config.json:117`).
  - `benchmark_hycal_timing_deconv.py` derives from the old benchmark (no LMS, no elastic-window). Its 25320 smoke test gave CB σ/E 5.98% against about 2.07% without deconvolution, with χ²/dof about 200 (`output/deconv_025320_smoke_cal_summary.csv`). The likely cause is that the deconvolution integral (template sum over pre = 8, post = 40 samples) is not the quantity `energize()` is calibrated against.
  - No NNLS `DeconvAnalyzer` exists, and pedestal autocorrelation is not measured.
- **Approach.**
  1. Fix the energy definition: on isolated pulses, measure the per-module ratio of the deconvolution integral to `pk.integral` and apply it.
  2. Add `--energy-estimator {integral,deconv-piled}` to the 20261021 benchmark, deconvolving only `Q_PEAK_PILED` channels (the production auto path), with per-module templates (item 1) and hybrid seeds (3b). Verify or replace the production template file (§4.3) before enabling `deconv-piled`.
  3. Build the NNLS `DeconvAnalyzer` with the measured pedestal autocorrelation for the paper's two-pulse separation result, evaluated on synthetic pile-up.
- **Success metric.**
  - Harness: on e-p, Δ_B no worse than the working point; on X17, Δ_B < 0 by more than 2 SE.
  - Synthetic: ΔT_min for 5% amplitude error.
- **Dependencies.** Items 1 and 3b. It shares the per-pulse fit with 4b.
