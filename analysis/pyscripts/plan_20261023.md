## 1. Goal and approach

**Goal.** Reduce the energy-independent part of σ_E/E of single-cluster elastic e-p events in the PbWO4 inner ring, on local data only, through three levers that act on the cluster energy definition rather than on pulse timing: (1) a per-crystal gain calibration that uses every cluster member, (2) a correction for the impact position inside the seed crystal, (3) neighbour amplitudes evaluated at the seed time without a detection threshold. Each lever is an option of the benchmark, off by default, measured with the same harness and the same paired statistics as Phases 1–4, against the mf baseline on the same splits.

**Approach.** Phase 0 (done during planning, §2) fits the resolution curve and bounds the calibration share of the constant term from the existing TSVs. Phase 1 adds the member list and the cluster position to the benchmark's per-event record, writes a compact per-event dump of the calibration pool, and implements the per-crystal χ² solve as `--cal-method percrystal` (plus `--gain-file` to apply pooled gains). Phase 3 adds the seed-time amplitude evaluation as an mf option. Phase 2 maps E/E′(θ) against the impact point from the dump, then applies the derived correction. Phase 4 runs the quick checks. Order 0 → 1 → 3 → 2 → 4 (§8).

**Rejected alternatives (one line each).**
- Re-deriving the calibration file with the C++ `physics_calib` (seed-indexed, 5×5 sum, separate invocations per iteration; `analysis/tools/physics_calib.cpp`): it is the method whose neighbour error we want to remove.
- Applying per-crystal gains before clustering via `HyCalSystem.set_calib_constant` as the default: it changes seeds, splitting and positions, so the comparison with the seed-indexed refinement would not be on the same clusters; kept as an option (D3).
- Per-module position-correction coefficients (PRad-1 style, 8 per module): 264 × 8 parameters need far more statistics than one split per module provides; a global map first.
- Fitting the neighbour time together with the amplitude (two-parameter, free): reintroduces the noise bias the option is meant to remove; a bounded ±2 ns search is kept only as a fallback (§5.1).
- A C++ change to let negative member energies through `AddHit`: not needed for the default; flagged in §9 if the clamping bias turns out to matter.
- An offline re-thresholding of island members as the "threshold scan": re-thresholding is not re-clustering (BFS connectivity changes), so the scan runs through the harness as the brief asks (§7).

## 4. Phase 1: per-crystal calibration

### 4.1 Record and dump (benchmark)

- Extend the per-event tuple (F2) by `members` (two aligned arrays: module index, energy in MeV as clustered, i.e. LMS-corrected, energized, split-scaled), `x_cl` and `y_cl` (`r.hit.x/.y`). Both paths. Memory: ≤ 160k events × ~12 members per split.
- `--cluster-dump PATH` (off by default; `auto` = `<out_path>_dump.npz`): one NPZ per job holding the **calibration pool only** (single cluster with E > `signal_min`, seed r < `inner_radius`, seed E ≥ `min_seed_energy`; the rectangle is *not* applied so D1 can be studied offline), **legacy path only**: `evnum, seed_idx, E_cluster, E_seed, x_cl, y_cl, x_seed, y_seed, size_x, size_y, theta_deg, eprime_MeV, emoller_MeV, f_lms` and CSR member arrays `ptr, midx, E` (float32). Header JSON with the run, split, flags, calibration file sha1, pulse method, `schema = 1`. About 8 MB per split. Dump set: S_dev (36 splits, ≈ 0.3 GB).

### 4.2 Solver (new module `percrystal_calib.py`, used in-benchmark and offline)

Minimise over gains g (one per PbWO4 module that appears as a member)

  χ²(g) = Σ_k w_k ( Σ_i g_i E_ki − E′_k )² + Σ_i λ_i (g_i − 1)²

- k runs over pool events inside their seed module's elastic window; i over members. E′_k = E′(θ_k) with θ from the seed centre as today (F1; the cluster-position θ differs by < 0.1 MeV at these angles). w_k = 1/σ²_glob (constant per run; kept explicit so a Huber weight can be slotted in if the held-out test shows a tail bias).
- Normal equations `(AᵀWA + Λ) g = AᵀW E′ + Λ·1`, A sparse (scipy `csr_matrix`; `scipy.sparse.linalg.spsolve` or dense `numpy.linalg.solve` on ≤ 400 modules). The diagonal D_ii = Σ_k w_k E_ki² is the module's effective statistics.
- **Regularisation:** λ_i = D_min, with D_min the diagonal a module would have from 30 seed events (`min_per_module`) at the mean seed fraction: D_min = 30·(0.64·E′)²·w. A module with D_ii ≫ D_min is free; one seen only as a faint neighbour is pulled to the calibration-file value g = 1. The prior fraction λ_i/(D_ii + λ_i) is written per module. Modules never seen, glass and Veto: g = 1 fixed.
- **Iteration:** (1) E_cal,k = Σ g_i E_ki with the current g (start: g = 1, or the seed-indexed solution for the initialisation-independence check); (2) per seed module the existing pre-fit/window/Møller machinery of F1 on E_cal (reuse `fit_elastic_window_gains`'s per-module block, refactored into a function that returns the window per module without computing a gain); (3) solve; (4) stop when max_i |Δg_i| < 1 × 10⁻³ over modules with prior fraction < 0.5, or after 6 iterations (report which). Expected: 3–4 iterations.
- Output per module: `module, index, row, col, g, sigma_g` (from the inverse normal matrix), `n_seed, n_member, D_ii, prior_frac, g_seedindexed` (for comparison) `, used`. In-benchmark: `<out>_gains.tsv` beside `<out>_window.tsv`. Offline pooled fits: `output/percrystal/<run>/gains_<run>_<even|odd|all>.tsv` (+ `.json` with provenance: runs, splits, iterations, convergence, flags, calibration file sha1). **Never under `database/`.**

## 5. Phase 3: seed-time-constrained neighbour amplitudes (mf option)

Listed before Phase 2 because it runs second (§8).

### 5.1 Definition

In mf mode, **per path** (`cl_legacy` and `cl_new` separately, F6): if the path has exactly one cluster with E > `signal_min`, its seed and neighbourhood are taken from that path's cluster; a path with 0 or ≥ 2 such clusters is left unchanged and counted (`n_skipped_<path>`). After the first `form_clusters` of the path:

1. Seed = `r.cluster.center`; its hit time t_s (offset-corrected, F6). Neighbourhood N = the seed's 3 × 3 (`--mf-nb-window 3`, default) or 5 × 5 (`5`) PbWO4 modules from `p.hycal.for_each_neighbor` / `qdist_modules` (F5), excluding dead modules and glass.
2. For every module i in N with a waveform row (`r ≥ 0`; WA-fallback channels keep their value and are counted): predicted onset `t0_i = (t_s + toff_i) − t50[m_i]`; amplitude `A_i = ⟨y_i, s_i⟩ / ⟨s_i, s_i⟩` over the kernel window at `t0_i`, with y_i = Y[r] − ped[r] (new `TemplateBank.amp_at(y, m, t0)` built from `_basis`/`_window`, batched over the neighbourhood; the K = 1 closed form of `_group`). **No threshold, no `min_amp`, no `r_model`.** Fallback only (`--mf-nb-time search`, used if P3-2 shows a loss at 0.73 GeV): evaluate at t0_i + {−2, −1, 0, +1, +2} ns and take the largest A.
3. Energy `E_i = energize(A_i · iint(m_i, t0_i) · κ · f_LMS)` exactly as for detected pulses (`pulse_energy_units`). Negative A clamps to 0 in `energize` and `AddHit` drops < 1 MeV (F3): the clamping bias per empty channel is ≈ +0.4·σ_A·iint·κ·factor (order 0.3 MeV); measured in P3-3.
4. Replace, for the modules of N, the hit list by the single hit `(t_s, E_i)` (also when a pulse was detected there: the constrained amplitude is the estimator for the whole neighbourhood, so detected and undetected neighbours are treated alike); all other channels keep their mf hits. Re-run `form_clusters` for that path on the replaced hit list (one extra C++ call per event and path; cost negligible against the batched MF). If the seed changes, keep the event and count it (`n_seed_flip`).
5. Header: `# mf_nb window=3 time=fixed offsets=<auto|off> n_events=.. n_replaced=.. n_fallback=.. n_skipped_legacy=.. n_skipped_new=.. n_seed_flip=.. mean_E_empty_MeV=..`.

Requires `--time-calib auto` (F7): the benchmark exits 2 if `--mf-nb-amp seedtime` is given with `--time-calib off`.

Why this helps: the mf detection threshold on a neighbour is max(5σ_A, 5 ADC) in amplitude; at a typical factor 0.14–0.17 MeV per integral unit and iint ≈ 7 samples, 5 ADC is ≈ 5–6 MeV per channel, five times the C++ member threshold. Corner neighbours and the outer 5 × 5 ring of a 0.73 GeV shower sit at or below that, so their energy is in or out event by event (a noise-like term, §2.1 item 4). The constrained amplitude is linear, unbiased by the threshold and by the noise-driven time fit, and its error is √(Σ s²)⁻¹·σ ≈ 0.47σ_raw per channel.

| Flag | Default | Meaning |
|---|---|---|
| `--mf-nb-amp {off,seedtime}` | `off` | Enables §5.1; ignored with `rawsum` |
| `--mf-nb-window {3,5}` | `3` | Neighbourhood (D2) |
| `--mf-nb-time {fixed,search}` | `fixed` | Onset at the seed time; `search` is the fallback of §5.1 step 2 |

## 6. Phase 2: position-dependent correction

### 6.1 What position the Python path has

`r.hit.x/.y`: the C++ log-weighted centroid over the seed's 3 × 3 (T = 3.6; F3), uncorrected, in mm; the seed centre and size from `p.hycal.module(index)`. Impact coordinates in crystal units: u = (x_cl − x_seed)/size_x, v = (y_cl − y_seed)/size_y; nominal range ±0.5 (the log-weighted centroid is biased toward the seed centre, the PRad-1 S-shape; the map is defined in **reconstructed** coordinates and applied in the same coordinates, which is all a correction needs; a GEM-based true position is out of scope). Resolution per event ≈ 2–3 mm (0.1–0.15 crystal units), from `hycal_clustering.md` figures; the map bins are 0.1.

### 6.2 Map (2a: offline on the dumps, no scan)

`position_corr.py map --dumps <glob> --gain-dir output/percrystal/ --out output/poscorr/<runtype>/` (the run of each dump comes from its header; the matching `gains_<run>_all.tsv` is applied): for pool events inside their seed's elastic window, R = E_cal/E′(θ) (per-crystal gains applied), binned in (u, v) with 12 × 12 bins over ±0.6, per run type, **global** (all seeds pooled). Per bin: median R, its MAD/√n error, n. Deliverables: the map as TSV and PNG, the peak-to-peak and population-weighted RMS amplitude, the projections R(|u|) and R(|v|), and the symmetry check (u → −u, v → −v). Statistics: ≈ 28k in-window events per split (§2.2), so 8 splits of 25320 give ≈ 1.5k events per bin (0.05 % precision) and the 10 splits of 24503 or 24590 ≈ 2k; the measurement is limited by the position resolution, not statistics.

**Gate:** if the global map's population-weighted RMS over bins is < 0.3 %, the achievable gain is < 0.04 pp at 3.49 GeV and 2b is skipped (report only).

### 6.3 Correction (2b)

- Form (D4): the binned map with bilinear interpolation (default), or the PRad-1 polynomial `R(u, v) = c0 (1 + c1u² + c2v² + c3u²v² + c4u⁴ + c5v⁴ + c6u + c7v)` fitted to the map (cite F4; the linear terms absorb the asymmetry of the 4-connected island). Global per run type.
- Apply: `E_corr = E_cal / R(u, v)` per event, after per-crystal gains, before the seed-indexed step (which then absorbs the residual mean per seed). Benchmark flag `--pos-corr FILE` (JSON: form, run type, bins or coefficients, provenance); header `# pos_corr=<path> sha1=.. form=.. rms_map=..`. One file per run type; passed per run through the `{runtype}` placeholder (§9).
- Validation on held-out splits (the map from the even splits, applied to the odd ones, and vice versa): paired Δσ/E per run type (preferred fit, legacy), mean ± SE. **Success: |Δ| > 2 SE and Δ ≤ −0.02 pp at 2.24 or 3.49 GeV.** The chosen form goes to S_full (§8 column "+ poscorr").

## 11. Risks and compatibility

| Risk | Mitigation |
|---|---|
| The per-crystal gain is determined mostly by seed entries (Σ f² of a module as a neighbour is ~3 % of its seed share), so g_i ≈ g_M and the held-out gain is small (§2.2 expects ≤ 0.04 pp) | Stated expectation; P1-4 reports the number with SE; P1-7 lists the modules where the two differ, which is where any gain comes from |
| Least squares inside a ±2σ window is pulled by the radiative tail differently for modules with different σ_M | P1-5 (seed-indexed on top must return 1 ± 0.5 %); a Huber weight is the fallback, one switch in the solver |
| Edge-of-ring modules seen only as neighbours are prior-dominated and inherit the calibration-file error | Prior fraction written; pooled fits over all splits of a run; modules with prior fraction > 0.5 counted in the hand-off |
| The seed-time option relies on the one global offset table (rawsum-derived, validated at 2.24 and 3.49 GeV, 0.67 ns) holding at 0.73 GeV, where Phase 3's headline lives | P3-2 measures the seed–neighbour Δt after offsets and the amplitude ratio on 24590.00010; the `search` fallback (F7: 5 % loss at 2 ns) is run only if it fails |
| Clamping of negative constrained amplitudes biases empty channels by ≈ +0.4σ_A | P3-3 measures it; 3 × 3 default limits the number of empty channels; C++ change flagged (§9) |
| Replacing detected neighbour pulses by constrained amplitudes changes pile-up handling in those channels (a second in-time pulse is no longer separated) | Only the selected cluster's neighbourhood is touched; `n_multi` in those channels reported; the `single-pulse` cuts stay available |
| The position map is in reconstructed coordinates; the log-weighted centroid compresses the edges, so the outer bins are populated by true edge hits of several positions | Map and correction share the same coordinates; 2a reports the population per bin; the polynomial form (D4) smooths sparse bins |
| Dump disk use (≈ 0.3 GB for S_dev, legacy path, pool events only) | 136 GB free; S_full is not dumped |
| The benchmark and harness are untracked; a scan during an edit would use a half-edited script | Scratch copy before editing (P1-1); edit and scan only when `pgrep -fl benchmark_hycal_timing` is empty |
| Harness changes (§9) touch job planning and `restable` | Dry-run before every stage; the stored command per job is unchanged for existing tags |
| Other scans compete for the 18 CPUs | Wall times assume exclusive use |

**Compatibility.** Default outputs and schemas of the benchmark, the driver, `gate_scan_20261021.py`, `output/gate_scan_20261021/`, `output/scan_20261021_full/`, `output/scan_20261022_mf/`, `output/gate_scan_20261022/`, `notes/`, `database/` and all C++ are not modified. Nothing is committed.
