# P7: calibration beyond the pool (2026-11-13)

Question: do measured per-module gains (and position correction, shape factor) for the modules outside the ep pool, trained on their own ep clusters and judged out of sample, lower the resolution of the H, M, O and T rings (D2) without moving the pool? Binding: U1 (PbWO4 rings only), U2 (gap reported, held-out judgement), D3, D4, D13.
Control: `variants/P7/ctrl/<RT>` = control v2 defaults with `EVAL_REGIONS=True` (pool rows equal `control_phase2_v2_20261113` to every digit, 0.73 / 3.49 / 3.49 old / Ta checked; D8). Gates: 12 ns and the control gate; tables below are legacy path (the control-gate path gives the same picture, see tsv). Runs: `output/energy_resolution/variants/P7/<variant>/<RT>/`, driver `run.sh`, tool `tools/p7_table.py`, table `P7_beyond_pool.tsv` (D12). Benchmark sha1 at the last run 843782c7 (the file's later edits are comments and other packages'; `variants/P7/benchmark_final.sha1` is the current sha). Units: `res_cb` in %, Δ = variant − control in pp, paired SE over (run, split); oos = even/odd cross fit per run (D1); gap = oos − in sample.

## Benchmark edits (additive, `--set`, default unchanged: `ctrl_v` rerun with the final file is bit-identical to `ctrl` in summary / regions_splits / gains / splits)

- `TRAIN_REGIONS` (tuple of H, M, O, T): the first-pass pool of `report` also holds the legacy clusters seeded there. `module_set(ref=)`: the global elastic scale (<E'>, pooled peak) stays set by the pool clusters; every seed module is windowed and solved by the existing member ridge solve (prior λ, `MIN_PER_MODULE` 30, convergence rule unchanged).
- `GAIN_COMBINE_RUNS`: the region modules' gains come from one solve over all runs of the run type (pool modules keep per-run gains); `GAIN_COMBINE_LOO`: run r's region gains from the other runs only (run-level held out, shown in the "in" columns).
- `GAIN_REGION_SCOPE`: `calibrate` returns the pool-only calibration (the control) plus the calibration trained on pool + regions (`<out>/ring/`), and `region_rows` applies the latter only to clusters seeded in `TRAIN_REGIONS`. Pool rows are then the control's by construction (all pool Δ in the tables are 0.000, Ta included).
- `TRAIN_PC_REGIONS` (position map, own polynomials and shape factor also fitted on the regions), `GAIN_RING_PRIOR_X` (λ multiplier for region modules), `GAIN_FREEZE_POOL` (negative, see below). New output `gains_regions.tsv` (per run and region: modules, rows, free, prior, converged), written with `EVAL_REGIONS`.
- Superseded: variants run while a worker-global fork bug was present (`variants/P7/_superseded/`: `p4`, `it12`, `loo`, `scpc_H`, `sccrpc_M`, `sccr_all_partial`) were rerun after the fix; `sccr_all` was rerun and reproduces the earlier run to every digit.

## Findings

1. **H ring (r < 85 mm hole ring, rows 15-20 × cols 15-20): large gain at ≥ 2.24 GeV.** res_cb oos 2.19 → 1.89 (2.24), 2.42 → 1.73 (3.49), 3.09 → 2.24 (3.49 old); the ring comes within 0.07 pp of the pool at 2.24 GeV (pool oos 1.82) but not at 3.49 (1.54 / 1.51), `eff_cut` +1.4 / +5.5 / +5.8 pp, `tail_lo_f` −0.4 / −4 / −4.4 pp, `sep_pi` +0.47 / +0.68 / +0.64. Ring-module gains held out by run keep the gain (−0.44 / −0.70 / −0.51; the pool-module gains of run r are still its own joint solve, so this is partly held out). Δ μ oos (pp): H +0.62 / +1.55 / +1.96 / +0.55 (2.24 / 3.49 / 3.49 old / 0.73; control −0.37 / −1.19 / −1.66 / −3.23), M +0.01 / +0.30 ± 0.26 / −0.40 / −0.25 (control +0.10 / −0.25 / +0.83 / +0.61): the ring peak moves toward E' (H) or scatters within ±0.4 % (M). At 0.73 GeV the elastic and Møller peaks cannot be told apart in H (ep − Møller gap below 3 σ_M for all 32 modules by a kinematics estimate; 0 seeded), the solve has nothing clean to train on and the ring gets worse (+0.12): keep H out at 0.73 GeV. The H gain mostly absorbs the hole-leakage deficit (H μ −0.5 to −2.6 % in P2) into module scales; it is a calibration for H-seeded clusters only, which is why it must stay scoped.
2. **M ring (200-300 mm): real, smaller gain.** oos −0.06 (2.24), −0.12 (3.49), −0.21 (3.49 old), −0.46 (0.73 GeV); `tail_hi_f` and `leak_cut` improve at every energy. The ring has 27-67 k clusters over 348 modules, so 311-348 modules reach ≥ 30 seed clusters only when the runs are combined; per-run solves (`scM`) overfit (2.24: in −0.07, oos +0.002; gap +0.07). U2 gap clause fires (+0.03 to +0.28 pp over the control's ≈ 0). Ring gains held out by run (LOO): 2.24 −0.065 (gap +0.006), 3.49 old −0.246, but 3.49 null (−0.010 ± 0.013: only one other run, 148 seeded modules). A 4× stronger prior on ring modules (`sccr_all_p4`) costs 10-32 % of the gain (M oos −0.053 / −0.081 / −0.144 vs −0.059 / −0.115 / −0.211) and halves the gap at 3.49 GeV only (+0.037 vs +0.084; 2.24 +0.030 vs +0.033).
3. **O and T: null.** Seeded modules 202 / 18 / 31 of 252 (O) and 71 / 1 / 2 of 256 (T) at 2.24 / 3.49 / 3.49 old; oos Δ within ±2 SE at every energy. They stay on the prior (0.45-1.00); the ep sample (5-15 k O clusters, 3-10 k T) cannot constrain them, and T's deficit is a boundary effect (P11), not module scales. Møller pairs and snake-scan / cosmic data (P14) are the only ways to add statistics; not run here (NL fix first per the P7 block, and U3 keeps non-linearity off).
4. **Position correction and shape factor on the regions: not beneficial.** Fitting the map and shape factor on pool + H + M + O + T (`sccr_pc`) is dominated by H clusters (2.9 M vs 1.1 M pool) and ruins M, O and H at 2.24 GeV (+0.46 / +0.49 / +0.72). Own H polynomials alone (`scpc_H`) help at 3.49 (−0.83 vs −0.69, old −1.55 vs −0.85) and hurt at 2.24 (+0.73), so they are not stable. M-only (`sccrpc_M`) equals the gain-only result (no M module has ≥ 1000 clusters, the map barely moves). Keep map and shape factor pool-trained.

## Recommendation (calibrated acceptance)

- **M ring: move in at 2.24, 3.49 old and 0.73 GeV** (oos gain real, LOO real where tested) as a ring-scoped calibration from all runs of the run type. The U2 gap clause as written (growth > max(2 SE, 0.02 pp)) fires, so this is the user's call: the oos number already is the held-out estimate and is positive; for a stricter reading use the 4× prior (smaller; gap halved at 3.49 GeV only) or wait for a second 3.49 GeV run (LOO null with one training run).
- **H ring: candidate at ≥ 2.24 GeV, user's call.** Ring-scoped; 2.24 GeV comes within 0.07 pp of the pool, 3.49 GeV improves by 0.7-0.85 pp but stays above the pool. As written, U2 kills it at 2.24 and 3.49 (gap Δ +0.135 ± 0.008 and +0.118 ± 0.015; only 3.49 old passes, −0.129). Reasons to waive the clause: the control's H gap is −0.15 / −0.12 (oos better than in sample), so the variant's absolute gap is −0.01 and 0.00 pp, and the ring-module gains held out by run keep the gain. Not at 0.73 GeV.
- **O and T: no.** Keep as the prior; they remain outside the calibrated acceptance.
- Nothing changes in the pool (Δ 0.000 at all five run types, Ta rerun after the fix included), in Ta rings (no M / O / T module reaches ≥ 30 seed clusters; H has 15 seeded modules of 32 but Ta H oos Δ +0.83 ± 1.68), or in any default.
- Not in the benchmark default: ring-scoped constants need a production consumer (per-cluster seed-ring lookup in the energy reconstruction); that is a deployment decision.
